Target: `index.html` (1754 lines) + `app.css` at commit `6d2e21e` ("Merge: scoate tab-ul Finalizate").

**Coverage gaps, honestly:** no two-client Firebase test — the local harness forces `hasAuth = false`,

## Findings

### 1. A finalized project can never be reopened — High — CONFIRMED
`index.html:801` is the only `data-close-project` control; nothing renders a reopen.
Commit `78f65c6` deleted `renderFinalizate`, and with it the `[data-reopen-fin]` handler that was the
sole place setting `p.finalizat = false`. Its message claims delivered projects "se redeschid din rândul
lor" — they don't.
**Repro:** expand any project at Montaj → Finalizează ✓ → switch the filter to Finalizate → expand the
row. Buttons offered: `📋 Materiale`, `Finalizează ✓`, `⋯`, `Editează`, `Șterge`, stage controls,
`+ Reparație`. No reopen. `Editează` doesn't expose `finalizat` either (`showStageField` at :1496 hides
the stage select for finalized projects and there is no checkbox).
Recovery is Ctrl+Z — which is gone after a reload or any colleague's save (see #8).
**Direction:** render `Redeschide` in `renderRegHead` when `p.finalizat`, restoring the old handler
(`p.finalizat = false` + `logEvent('redeschis', …)`), and clear `finalizatAt`.

### 2. "Finalizează ✓" still shows on an already-delivered project — High — CONFIRMED
`index.html:770` — `finalizabil = isPostExecStationFor(p, p.stationId) || …` never checks `p.finalizat`.
**Repro:** finalize a project at Montaj, expand its row again → the button is still there. Clicking it
runs :1034 again: overwrites `finalizatAt` with today's timestamp (destroying the real delivery date,
which is what the row's date column shows) and POSTs a second `finalizat` entry to the Firebase log.
**Direction:** `finalizabil = !p.finalizat && (…)`; pair with #1 so the slot shows `Redeschide` instead.

### 3. An unrecognized `version` silently wipes the board — and writes the wipe back — High — PLAUSIBLE
`index.html:313-322`: `resolveVersioned` falls through to `return defaultState()` for any version it
doesn't know, with no error, toast, or log. It runs on every load **and on every live-sync snapshot**
(:1713).
**Scenario:** someone deploys `DATA_VERSION = 9`; a teammate still has the old tab open. Their listener
receives the v9 snapshot → `defaultState()` → `applyRemote` replaces `state` with an empty board and
toasts "modificări de la un coleg". Their next click calls `saveState()`, which `set()`s the empty
document over the whole team's data.
**Direction:** on an unknown/forward version, refuse the snapshot (return null and bail out of
`applyRemote` / show a "reîncarcă pagina" blocker) rather than substituting an empty board — and never
let a state derived from a failed resolve reach `saveState`.

### 4. Dropping a piece on Montaj moves the whole project, not the piece — High — CONFIRMED
`index.html:1140-1144`: if the drop zone is a post-execution `proiect` stage, the handler sets
`p.stationId`, not `pc.stationId`, and ignores the piece entirely.
**Repro:** 0012 Serban Rosca, at Proiectare (`s3`), 4 pieces spread over `s1`/`s6`/`__montaj__`. Drag the
`s1` piece onto the Montaj column → project moves `s3` → `s7`; the piece stays at `s1`. No confirm, no
cue that grabbing one piece will relocate the project. The row's phase tag flips PRG → MTJ.
**Direction:** either send the dragged piece to `PIECE_MONTAJ` (see #5) and leave the project alone, or
make the project move an explicit gesture (drop the *stage head* handle, which already exists) and have
the piece drop confirm.

### 5. Nothing can put a piece on `PIECE_MONTAJ` any more — High — CONFIRMED
`PIECE_MONTAJ` (`index.html:74`) is read at :301, :425, :838 and written nowhere — verified by grepping
every `stationId =` assignment. The move buttons that used to set it were removed; the drag path takes
branch #4 instead. The 6 pieces sitting at `__montaj__` in the live data are leftovers.
Consequence: the "montaj" count in the row strip (`nM`, :762) and the montaj column in the pipeline are
now write-once historical artifacts; the workflow step "piesa e gata, pleacă la montaj" has no UI.
**Direction:** wire it into the drop handler (#4), or drop the sentinel and the montaj bucket entirely.

### 6. Empty stage columns are a 31 × 8 px drop target — High — CONFIRMED
`app.css:300-302` (`.thin{flex:0 0 32px}`, `.thin .col-body{min-height:0; padding:4px}`) plus
`index.html:870/885/889`, which suppress the `—` placeholder when `thin`. Since move buttons were
removed, drag is the *only* way to advance a piece — and the common case (advance into the next, empty
stage) is the hardest possible target.
**Measured** on 0007 Clapan, viewport 1440: seven of eight columns were `thin` with a `col-body` of
exactly **31 × 8 px**. The column boxes are 64-150 px tall, but that height is the vertical stage-name
head, which is not a drop zone.
**Direction:** give `.thin .col-body` a real `min-height` (or make the whole `.proj-stage-box` the drop
target), and un-thin a column while a drag is in progress.

### 7. Deleting a project orphans its repairs, permanently and invisibly — Medium-High — CONFIRMED
`index.html:1042-1049` removes the project and leaves `state.repairs` untouched.
**Repro:** add a repair to 0007 Clapan → delete the project → `state.repairs` still holds
`{projectId:"mtgw502bq9nj0", cod:"0007 Clapan", …}`. It renders nowhere (the Reparații tab is gone), the
"Cu reparații" filter shows 0 rows, and because `repairsFor` (:537-541) prefers `projectId` when present,
recreating a project with the same `cod` will **not** re-adopt it. Orphans accumulate in the synced
document forever.
**Direction:** delete (or explicitly archive) `state.repairs` entries for the project on delete, and warn
in the confirm dialog when the project has any.

### 8. Lost update: a colleague's change is discarded if it lands while you're mid-edit — Medium-High — PLAUSIBLE
`index.html:1716` sets `remoteDirty = true` and *drops the snapshot* — nothing is stashed. `saveState`
(:367) then `set()`s your whole stale document. The `flushRemote()` in the `.then` (:373) re-reads the DB
*after* you overwrote it, so it can only ever confirm your own write; the colleague's change is gone with
no trace.
**Scenario:** you open the project modal (`userIsBusy()` true, :1665-1672) → a colleague changes a repair
status → you press Salvează → their change is silently reverted for everyone.
More generally, whole-document `set()` means any two writes seconds apart clobber each other regardless
of which projects they touched.
**Direction:** at minimum stash the incoming snapshot and refuse/warn on save when `remoteDirty` is set.
Properly: write per-project subpaths (`dbRef().child('projects/…').set(…)`) instead of the whole document.

### 9. Sorting by "Cod" throws and silently freezes the registru — Medium — CONFIRMED
`index.html:670-671` — `a.cod.localeCompare(b.cod)` with no guard.
**Repro:** any listed project without `cod` → picking "Cod" in the sort dropdown logs
`Uncaught TypeError: Cannot read properties of undefined (reading 'localeCompare')`. The exception escapes
the change handler *before* `board.innerHTML = html`, so the list keeps showing the previous sort — the
dropdown says "Cod" and nothing happened. `regSort === 'urgenta'` (:670) has the same exposure as a
tie-break.
Trigger likelihood is low today (the modal requires a non-empty cod), but nothing in `normalizeState`
guarantees the field.
**Direction:** `(a.cod || '').localeCompare(b.cod || '')`, and default `p.cod = ''` in `normalizeState`.

### 10. "1 piese" reported for a project with zero pieces — Medium — CONFIRMED
`index.html:763` — `var tot = Math.max(1, nP + nE + nM);` is a leftover divide-by-zero guard from the
progress bar that :787 replaced with a plain number.
**Repro:** four different pieceless test projects all showed
`1 piese  0 pregătire · 0 execuție · 0 montaj` in the expanded strip. (Grammar too: "1 piese" → "1 piesă".)
**Direction:** use the real total; keep `Math.max(1, …)` only if some divisor still needs it (nothing does).

### 11. A project whose `stationId` matches no stage is stuck — Medium — CONFIRMED
`normalizeState` heals *piece* `stationId`s (:299-305) but never `p.stationId`. And
`nextProiectStationFor` (:441-445) does `a[a.findIndex(…) + 1]`, so an unknown id yields `-1 + 1 = 0` →
it returns `a[0]`, which makes `finalizabil` (:770) false.
**Repro:** a project with `stationId: null` renders every pipeline column as `thin`, has **no `is-here`
column** and therefore no `[data-proj-drag]` handle, no `Finalizează ✓`, and `etapă: —`. The only way out
is Editează → Etapă curentă. Reachable if `state.stations` ever has no `proiect` stage when a project is
created (:1592), or from any externally-written data.
**Direction:** heal `p.stationId` alongside the piece ids in `normalizeState`; make
`nextProiectStationFor` return `null` when `findIndex` is `-1`.

### 12. `.reg-wide` sticks with nothing expanded — Medium — CONFIRMED
`index.html:659` — `anyOpen = Object.keys(registryOpen).length > 0` counts ids regardless of whether
those projects are in the current list, and nothing ever prunes the map.
**Repro (three ways):** expand a row → switch the filter to Finalizate → the registru stays at 100% width
with 0 expanded rows and the columns stretched over 1385px. Same with a search that matches nothing. Worst
case: **delete the project while its row is open** → the id stays in `registryOpen` forever, there is no
row left to collapse, and the layout stays wide until a reload.
**Direction:** compute `anyOpen` from the rendered list (`list.some(p => registryOpen[p.id])`) and delete
the key in the project-delete handler.

### 13. Keyboard focus is destroyed on every registru interaction — Medium — CONFIRMED
Every toggle/filter/sort/repair action calls `render()`, which does `board.innerHTML = html`.
**Repro:** focus a `.reg-row` (`document.activeElement.className === "reg-row ph-exec"`), press Enter →
the row expands and `document.activeElement` is `BODY`. A keyboard user has to Tab from the top of the
page after every single action. The registru is now the app's primary surface and its rows are `<button>`s,
so this is the main keyboard path.
Related: `aria-controls="reg-detail-<id>"` (:724) points at an element that only exists while expanded —
verified dangling on every collapsed row.
**Direction:** after `render()`, restore focus to the element with the matching `data-toggle-reg` /
`data-*` key; render the detail container always and toggle `hidden` on it.

### 14. Stage reorder (‹ ›) can silently break a project's flow — Medium — CONFIRMED (code path)
`index.html:849-850` render the arrows on every non-thin column; :996-999 swap array slots with no
type check. Moving the Montaj stage left of the last `piesa` stage makes `isPostExecStationFor` false →
`finalizabil` false → **the project can no longer be finalized**, with no explanation. Moving a `piesa`
stage changes `firstPiesaIndexFor` / `pieceFlowFor` / `bucketFor` for every piece at once, silently
re-labelling "pregătire" vs "execuție" counts.
**Direction:** constrain the swap to same-type neighbours, or validate the resulting order (all `piesa`
stages contiguous, at least one `proiect` stage after them) and refuse otherwise.

### 15. The activity log now records only two event types — Medium — CONFIRMED
Only `logEvent('finalizat', …)` (:1034) and `logEvent('proiect-nou', …)` (:1595) remain. `LOG_LABEL`
(:119) still declares `redeschis`, `avansat`, `piesa-montaj`, `furnizor-retur` — all emitter-less
(`redeschis` lost its caller in `78f65c6`, the others earlier). The "Istoric (.txt)" export was just
promoted into the feedback modal, so users will open it expecting a work log and find creations and
finalizations only.
**Direction:** either re-emit on stage advance / piece move / reopen from the drag and finalize handlers,
or drop the dead labels and rename the export so it doesn't over-promise.

### 16. Modals have no focus management, no Escape, no trap — Medium — CONFIRMED
`openProjectModal` / `openFeedbackModal` set `root.innerHTML` and stop. **Repro:** open "+ Proiect nou" →
`document.activeElement` is `BODY`; pressing Escape does nothing (verified); Tab walks straight out into
the page behind the overlay. Background click is deliberately disabled, so ✕/Anulează are the only exits.
**Direction:** focus the first field on open, add an Escape handler, and cycle Tab within `.modal`.

### 17. A repair with no `cod` attaches to every project with no `cod` — Low — CONFIRMED
`repairsFor` (:537-541) falls back to `normCod(r.cod) === normCod(p.cod)`, and `normCod` maps both
`undefined` and `''` to `''`. `normalizeState`'s migration (:269-273) correctly skips cod-less repairs,
so they never get a `projectId` and stay in the fallback path forever.
**Repro:** seeded `{id:'r4', descriere:'fara cod si fara projectId'}` → it appeared on the cod-less test
project's repair thread and in its 🔧 badge. Firebase prunes `cod: ""`, so any repair saved with an empty
cod lands here.
**Direction:** make the fallback require a non-empty cod on both sides.

### 18. Cod-only repairs bind to the first project with a matching cod — Low — CONFIRMED
`normalizeState:271` uses `.find`. With two projects sharing a cod, all legacy repairs go to whichever
comes first in the array — verified with two `T-DUP` projects. Deterministic but arbitrary, and the
migration is one-way (a `projectId` once written is never revisited).
**Direction:** skip the auto-link when more than one project matches, and surface those repairs for
manual assignment.

### 19. `finalizatAt.slice(0,10)` is UTC, the row is local — Low — PLAUSIBLE
`index.html:733` slices `new Date().toISOString()` (:1034). At UTC+3, a project finalized between 00:00
and 03:00 local shows the previous day in the row's date column.
**Direction:** store/derive the local date (`isoToday()` already exists) for display.

### 20. `render()` mutates `state` — Low — CONFIRMED
`projectLanesFor` (:480-486) writes `p.laneDefs[station.id]` from inside `renderRegPipe`.
**Repro:** merely expanding a row added `laneDefs` keys `s3` and `s6` to the persisted project — `s3`
(Proiectare) has no lanes at all, so it got an empty array. Harmless today (Firebase and `stableStringify`
both prune `[]`), but a render pass dirties the model, leaves `prevStateJson` transiently stale, and the
mutation rides along on the next unrelated save.
**Direction:** derive lanes without writing, or seed `laneDefs` in `normalizeState`.

### 21. Long `cod` collapses the client and the signal to zero width — Low — CONFIRMED
`app.css:221` — `.rr-cod` sits in the grid's `auto` track with `white-space:nowrap`, no `min-width:0`
and no ellipsis, while `.rr-cli` (`minmax(0,auto)`) and `.rr-sig` (`minmax(0,1fr)`) do have ellipsis and
therefore give way first.
**Measured:** an 85-char cod rendered at 727px → `.rr-cli` width 0 (content 621px) and `.rr-sig` width 0
(content 79px) — the single signal, the whole point of the redesign, vanishes rather than the cod
truncating. Realistic 50-62 char cods are fine at 1440px; the failure needs an extreme cod or a narrow
window between 600 and 900px.
**Direction:** `min-width:0; overflow:hidden; text-overflow:ellipsis` on `.rr-cod`, and give the signal a
protected minimum.

### 22. Long unbroken piece names overflow the card and the column — Low — CONFIRMED
`app.css:309` `.piece-card{flex:0 0 146px}` with no `word-break`/`overflow-wrap`/`overflow` on `.p-name`.
**Measured:** a 120-char single-token name produced a 921px card inside a `max-width:620px` column
(`col-body` scrollWidth 929 vs width 620, `overflow:visible`) — the card paints over its neighbours.
Names with spaces wrap fine, so this needs a long token (a part number, a pasted code).
**Direction:** `overflow-wrap:anywhere` on `.p-name` (and `min-width:0` on the card).

### 23. Dead code and dead data — Nit — CONFIRMED
Unreferenced functions: `urgencyLabel`(:489), `MONTHS`(:112), `sameDay`(:111), `addDays`(:106),
`isoOf`(:105). `stationById`(:417) survives only to serve the non-`data-project` branches of the lane /
`col-actions` handlers (:915-1030), which `renderRegPipe` can no longer reach — including the
`.col-title` listener at :915, for a class nothing renders. `hasCloudStorage` (:153, :208, :390) is the
Claude.ai artifact path. `state.checklists` (:138, :279, :307, :310) and `state.assignments` (:277) are
carried and normalized but never rendered. `sig.k === 'mat'` (:723) plus `.rr-sig.k-mat` (app.css:240)
is unreachable — `regSignal` only ever returns `done`/`late`/`blk`/`stage`. `p.ordersPinned` is in the
live data, never read and never deleted by `normalizeState` (unlike its sibling `montajPinned`).
`.rep-add-inp.bad` is added on empty submit (:1220) and never removed.

### 24. Opening the app deletes the team roster, unrecoverably — Nit — CONFIRMED
`normalizeState:277` — `parsed.workers = filter(kind === 'furnizor')`. The live data still holds 18
`kind:'intern'` workers; they are dropped on read and written out of Firebase on the reader's next save.
This happens before `resetUndoHistory` sets `prevStateJson`, so there is no undo point. Intentional per
the comment, but worth knowing it is a read-triggered destructive migration with no backup.

### 25. Bucket labels don't match calendar weeks — Nit
`regBucket` (:545-554): "Săptămâna asta" = 0-6 days out, "Săptămâna viitoare" = 7-13. On a Friday, a
Thursday-next-week deadline lands in "Săptămâna asta". Rolling windows labelled as calendar weeks.

### 26. Suggested project code collides after deletions — Nit
`index.html:1483` — `nextNum = state.projects.length + 1`. Delete a project, add one, and the suggestion
repeats an existing code.

## Clean / verified OK

- **`[hidden]` toggles.** `app.css:46` `[hidden]{display:none!important}` holds: `.reg-orders` (block),
  `.reg-more-body` (flex) and `.furn-panel-body` (flex) each measured 0px tall and `display:none` when
  closed, correct height when open. The earlier `display:flex` beats `[hidden]` bug is fixed.
- **`esc()` coverage.** `<img src=x onerror=…>` injected into `cod`, `client`, `notite`, `tip` and a
  repair `descriere` all rendered as inert text; no `window.__xss*` flag ever fired. I found no
  interpolation of user text into HTML without `esc()`.
- **Undo/redo.** Repair add, repair status cycle, project add, project delete, piece drag, and inline
  order-text edit each push exactly one undo point; ↶/↷ disabled states were correct at every step of a
  4-action sequence; undo restored both the data and the DOM. Inline edits that deliberately skip the
  re-render still keep the ↶ button in sync (`saveState` → `updateUndoButtons`, :364-366). Filter and
  sort changes push nothing.
- **`normalizeState` idempotency.** Every branch I traced is a no-op on a second pass. The cod→projectId
  repair migration correctly matched `"  t-manyrep  "` to `T-MANYREP` (trim + lowercase).
- **Piece stage healing.** A live-data piece with no `stationId` key at all was healed to the project's
  first stage; `p.stations` was re-seeded for a project with `stations: []`.
- **Lane drops.** On a station that has pieces, lane bodies measured 205 × 60 px and the drop wrote both
  `stationId` and `lane`; `defaultLaneId` correctly places a piece whose `lane` is unset.
- **Empty states.** 0 projects → "Atelier gol" with a working `+ Proiect nou`; 0 orders → the Comenzi
  empty state with the Furnizori panel intact. No errors either way.
- **Comenzi tab.** Supplier grouping, "— fără furnizor —" sorting last, "Arată și primite", inline edits,
  status cycling, row delete — all worked, no console errors, no stray undo points.
- **No listener accumulation.** `attachHalaEvents` binds only to elements just created by
  `board.innerHTML`. The document/window listeners (`resize`, `keydown`, `focusout`, `visibilitychange`)
  and the `setInterval(flushRemote)` are each registered exactly once (`liveSyncAttached` guards the
  sync ones). No `getElementById` in the hot paths returned null.
- **Firebase write discipline.** The board node is written from exactly one place (`saveState`, :367),
  and it calls `noteLocalWrite` first. `logEvent` and the feedback POST target separate nodes.
- **`daysBetween`.** `Math.round((b-a)/86400000)` is DST-safe for whole-day differences; `regBucket`'s
  `n < 0` and `regSignal`'s `getTime()` comparison agree on the late boundary.
- **`stableStringify` pruning** matches Firebase's (`null`, `[]`, `{}`, `""`), including the recursive
  case where a nested object becomes empty after its children are pruned. Left untouched as instructed.
- **Console** stayed clean through every interaction except finding #9.
